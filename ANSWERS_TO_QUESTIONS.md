## Вопрос 2: Celery - Group Results и Task Results

**Ваш вопрос:** "celery -> Group results, Task results" - что это?

**Ответ:** ✅ **Настроено, но Celery не запущен**

### Что это такое:

**Task Results** - результаты выполненных фоновых задач:
- ID задачи
- Статус (SUCCESS, FAILURE, PENDING)
- Результат выполнения
- Время выполнения
- Traceback при ошибке

**Group Results** - результаты групповых задач (когда несколько задач запускаются одновременно)

### Где посмотреть:
1. Откройте админку: `http://localhost:8000/admin/`
2. Найдите раздел **DJANGO CELERY RESULTS**
3. Кликните на **Task results** или **Group results**

### Интеграция:
- ✅ Модели настроены (`django_celery_results` в `INSTALLED_APPS`)
- ✅ Результаты сохраняются в БД (`CELERY_RESULT_BACKEND = 'django-db'`)
- ⚠️ **НО:** Celery Worker не запущен, поэтому результатов пока нет

### Как запустить:
```bash
celery -A core worker --loglevel=info
```

После запуска задачи будут выполняться и результаты появятся в админке.

## Вопрос 3: Запросы на отмену товара

**Ваш вопрос:** "Запросы: Отмена товара" - интегрированы ли?

**Ответ:** ✅ **ДА, полностью интегрированы**

### Где посмотреть:
1. Откройте админку: `http://localhost:8000/admin/`
2. Найдите раздел **ORDERS**
3. Кликните на **Запросы: Отмена ТОВАРОВ**

### Как работает:

**Со стороны пользователя (фронтенд):**
1. Пользователь открывает заказ
2. Кликает "Отменить товар"
3. Указывает причину отмены
4. Запрос отправляется в бэкенд

**Со стороны админа (админка):**
1. Админ видит запрос в списке
2. Может изменить статус на:
   - **Approved** (Одобрен) → товар автоматически отменяется
   - **Rejected** (Отклонен) → запрос отклоняется

**Автоматическая обработка:**
```python
# При одобрении запроса:
- order_item.is_canceled = True
- order_item.canceled_at = timezone.now()
- order_item.save()
```

### Интеграция:
- ✅ API: `/api/orders/{order_id}/items/{item_id}/cancel/`
- ✅ Модель: `orders/models.py` → `OrderItemCancellationRequest`
- ✅ Админка: `orders/admin.py` → `OrderItemCancellationRequestAdmin`
- ✅ Фронтенд: Есть кнопка отмены товара

## Вопрос 4: Акции интегрированы ли автоматически к цене?

**Ваш вопрос:** "Order -> Акции интегрированыли автоматически к цена то есть заказам и с клиентской стороны тоже не видно"

**Ответ:** ❌ **НЕТ, акции НЕ применяются автоматически!**

### Текущая ситуация:

**Что работает:**
- ✅ Модель `Promotion` существует
- ✅ Админка для создания акций есть (`/admin/orders/promotion/`)
- ✅ Фронтенд показывает акции в разделе "Акции"

**Что НЕ работает:**
- ❌ При добавлении товара в корзину акция **НЕ применяется**
- ❌ Цена берется из `product.price` без учета акций
- ❌ Пользователь видит акцию, но платит полную цену

### Пример проблемы:

```
Товар: Филадельфия
Обычная цена: 50,000 сум
Акция: -20%

Ожидаемая цена в корзине: 40,000 сум
Реальная цена в корзине: 50,000 сум ❌
```

### Почему не работает:

В коде добавления в корзину (`orders/views.py`):
```python
order_item, created = OrderItem.objects.get_or_create(
    order=cart,
    product=product,
    defaults={"price": product.price}  # ← Берется обычная цена!
)
```

Нет проверки активных акций!

### Как исправить:

📄 **Смотрите файл `FIX_PROMOTIONS_GUIDE.md`** для подробной инструкции

**Краткое решение:**
1. Добавить метод `get_discounted_price()` в модель `Product`
2. Изменить `defaults={"price": product.get_discounted_price()}`
3. Обновить API для отображения скидки

### Интеграция с клиентской стороной:

**Текущее состояние:**
- ✅ Фронтенд показывает список акций (раздел "Акции")
- ❌ Фронтенд НЕ показывает скидку на карточке товара
- ❌ Фронтенд НЕ показывает зачеркнутую цену

**После исправления будет:**
- ✅ На карточке товара будет зачеркнутая старая цена
- ✅ Рядом новая цена со скидкой
- ✅ Бейдж "Акция -20%"
- ✅ В корзине цена со скидкой

## Вопрос 5: Периодические задачи - в чем их задача?

**Ваш вопрос:** "Периодические Задачи, Contrab, Астрономические события, Время, Интервалы - суть: в чем их задача в этом проекте интегрировани ли они к чему не понятно почему они существуют?"

**Ответ:** ⚠️ **Настроены, но НЕ используются**

### Что это такое:

**Celery Beat** - планировщик задач (аналог cron в Linux)

**Типы расписаний:**

1. **Crontab** - как в Linux cron
   ```
   Пример: Каждый день в 9:00
   Minute: 0
   Hour: 9
   Day of week: *
   Day of month: *
   Month: *
   ```

2. **Interval** - интервалы
   ```
   Пример: Каждые 10 минут
   Every: 10
   Period: Minutes
   ```

3. **Solar** - астрономические события
   ```
   Пример: На восходе солнца
   Event: sunrise
   Latitude: 40.1288875
   Longitude: 67.8244219
   ```

4. **Clocked** - одноразовое выполнение
   ```
   Пример: 2025-12-25 12:00:00
   ```

### Зачем они нужны в вашем проекте:

**Примеры задач, которые ДОЛЖНЫ быть:**

1. **Проверка статуса оплаты** (каждые 10 минут)
   - Задача: `check_order_payment_status`
   - Цель: Найти "зависшие" заказы и проверить их в Click API
   - Расписание: Interval (каждые 10 минут)

2. **Очистка старых корзин** (каждый день в 3:00)
   - Задача: пока не создана
   - Цель: Удалять корзины старше 7 дней
   - Расписание: Crontab (3:00 каждый день)

3. **Отправка отчетов** (каждый день в 23:00)
   - Задача: пока не создана
   - Цель: Отправлять администратору отчет о продажах
   - Расписание: Crontab (23:00 каждый день)

4. **Напоминания о незавершенных заказах** (каждый час)
   - Задача: пока не создана
   - Цель: Напоминать пользователям о неоплаченных заказах
   - Расписание: Interval (каждый час)

### Интегрированы ли они:

**Статус:** ⚠️ **НЕТ, не интегрированы**

**Что настроено:**
- ✅ `django_celery_beat` установлен
- ✅ Админка для создания задач есть
- ✅ Задачи созданы (`orders/tasks.py`)

**Что НЕ настроено:**
- ❌ Celery Beat не запущен
- ❌ Периодические задачи не созданы в админке
- ❌ Расписания не настроены

### Как запустить:

**Шаг 1: Запустить Celery Beat**
```bash
celery -A core beat --loglevel=info
```

**Шаг 2: Создать периодическую задачу**
1. Откройте `/admin/django_celery_beat/periodictask/add/`
2. Заполните:
   - **Name:** "Check Payment Status Every 10 Minutes"
   - **Task:** `orders.tasks.check_order_payment_status`
   - **Enabled:** ✅ Да
3. Создайте интервал:
   - **Every:** 10
   - **Period:** Minutes
4. Сохраните

**Шаг 3: Проверить**
```bash
# В логах Celery Beat увидите:
[INFO] Scheduler: Sending due task Check Payment Status Every 10 Minutes
```

### Почему они существуют:

**Причины:**
1. **Автоматизация** - не нужно вручную проверять заказы
2. **Надежность** - задачи выполняются даже если админ забыл
3. **Масштабируемость** - можно добавлять новые задачи без изменения кода
4. **Удобство** - настройка через админку, а не через код
